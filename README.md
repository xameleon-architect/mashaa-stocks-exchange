# Mashaa: МойСклад → Tilda — синхронизация остатков

Версия 0.4 предназначена только для тестового контура.

## Что делает инструмент

- читает товары, модификации и остатки выбранного склада из JSON API МоегоСклада;
- рассчитывает `Доступно = Остаток − Резерв + Ожидание`;
- сопоставляет позиции по `externalCode` МоегоСклада и `External ID` Tilda;
- формирует аудит CSV и пакет CommerceML `import0_1.xml` + `offers0_1.xml`;
- по умолчанию работает только в `dry-run`;
- записывает остатки в Tilda только после явного подтверждения;
- считает пакет отправленным только после успешного CommerceML-обмена, но не помечает изменение подтверждённым без проверки каталога Tilda;
- поддерживает постоянный dry-run раз в минуту; постоянная запись временно заблокирована до появления автоматической проверки результата Tilda.

Инструмент передаёт минимальную ссылку на изменяемый товар, связь варианта и остаток. Изображения, полные описания, цены и заказы не передаются.

## Требования

- Windows 10/11;
- Python 3.11 или новее;
- доступ компьютера к `api.moysklad.ru` и `store.tilda.ru`;
- токен тестового МоегоСклада;
- новые реквизиты CommerceML тестовой Tilda.

## Установка

1. В тестовом МоемСкладе откройте **Меню пользователя → Настройки → Токены**.
2. Нажмите **+ Токен**, назовите его `Mashaa Tilda Sync Test` и скопируйте значение. Это отдельный токен JSON API, а не пароль CommerceML.
3. Распакуйте архив в отдельную папку без кириллицы, например `C:\Tools\mashaa-tilda-sync`.
4. Запустите `install.bat`.
5. Откройте созданный файл `.env` в Блокноте.
6. Заполните четыре значения:

```env
MOYSKLAD_TOKEN=...
TILDA_CML_URL=https://store.tilda.ru/connectors/commerceml/
TILDA_CML_LOGIN=...
TILDA_CML_PASSWORD=...
```

Не присылайте `.env` в чат и не добавляйте его в Git.

## Первый безопасный запуск

Запустите `run-dry.bat`. Скрипт прочитает МойСклад, но не отправит данные в Tilda.

Успешный результат выглядит примерно так:

```text
Summary: matched=165/165, unmatched=0, changes=0, mode=dry-run
Exit code: 0
```

В папке `output` появятся:

- `audit-*.csv` — таблица изменений;
- `offers-*.xml` — подготовленный CommerceML;
- `summary-*.json` — контрольные итоги.

Если есть `unmatched > 0`, не запускайте режим записи. Пришлите `summary-*.json` и `audit-*.csv`; секретов в них нет.

## Первый тест записи

1. В МоемСкладе измените остаток одной тестовой модификации с 10 на 3.
2. Запустите `run-dry.bat` и убедитесь, что в аудите ровно одно ожидаемое изменение.
3. Запустите `run-apply-once.bat`.
4. Введите `APPLY-TEST-TILDA`.
5. Проверьте остаток нужного варианта в Tilda.

## Постоянная синхронизация

После успешного одиночного теста запустите `run-watch.bat`. Синхронизация выполняется не чаще одного раза в 60 секунд. Остановить её можно сочетанием `Ctrl+C`.

Для боевого запуска лучше использовать Планировщик заданий Windows или серверный процесс. Это отдельный этап после подтверждения теста.

## Защитные механизмы

- режим записи не включается случайно;
- при совпадении менее 98% позиций работа останавливается;
- дубли `External ID` и `externalCode` останавливают обмен;
- отрицательное доступное количество передаётся как ноль;
- дробные количества запрещены;
- повторный процесс блокируется файлом `sync.lock`;
- токены и пароли не записываются в логи;
- временные результаты заменяются атомарно.
- session cookie CommerceML не сохраняется в summary; старые summary автоматически очищаются;
- постоянный режим записи заблокирован, пока применение изменений нельзя подтвердить автоматически.

## Настройка

Основные параметры находятся в `config.json`:

- `store_name` — точное название склада МоегоСклада;
- `watch_interval_seconds` — период, минимум 60 секунд;
- `minimum_match_ratio` — минимальная доля сопоставления;
- `clamp_negative_to_zero` — обнулять отрицательное доступное количество.

## Возможные ошибки

### `Missing environment variable`

Не заполнено соответствующее поле в `.env`.

### `Expected one store named ...`

Название в `config.json` не совпадает с названием склада в МоемСкладе.

### `Match ratio ... is below required`

External ID Tilda не совпадают с `externalCode` МоегоСклада. Запись заблокирована.

### `CommerceML checkauth failed`

Проверьте новый логин и пароль CommerceML и повторно сохраните подключение в МоемСкладе/Tilda.

### Остаток не изменился после успешного импорта

Не запускайте повторную полную выгрузку. Сохраните `summary-*.json`, `offers-*.xml` и лог текущего дня — по ним нужно уточнить формат, который фактически принимает Tilda.

## Важное ограничение версии 0.4

Последовательность CommerceML реализована по схеме Tilda: `checkauth → init → file import0_1.xml → file offers0_1.xml → import import0_1.xml → import offers0_1.xml`. Файл каталога помечен как содержащий только изменения и не содержит товаров; скрипт не заменяет карточки. Реакцию тестового коннектора необходимо подтвердить живым запуском. До этого версия считается кандидатом, а не проверенной боевой интеграцией.
